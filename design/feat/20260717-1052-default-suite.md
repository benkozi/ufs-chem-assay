# Feature: regex suite selector + `.env` support

## Goal

Keep `uv run pytest` bounded as the suite library grows: a bare invocation
always runs exactly one suite — `simple-maccity-suite.yaml` — never "whatever
is lying around". Replace `--suite-config`'s path semantics with a **regex
selector** resolved against suites discovered recursively under one or more
search directories (`CECE_SUITE_CONFIG_SEARCH_PATH`), and add `.env`-file
support so per-machine configuration (`cece_root_dir`,
`cece_baseline_root_dir`) needs no shell exports.

## Pre-design audit of the current selection path

1. **`--suite-config` is a path today.** Default is the absolute path of the
   checked-in `src/tests/config/suite/simple-maccity-suite.yaml`
   ([conftest.py:26](src/tests/conftest.py)); relative values get
   `suite_config_search_path` (a single directory, kept whole) prepended in
   `resolve_suite_path` ([resolution.py:32](src/resolution.py)); absolute
   values pass through. Missing files surface as `UsageError` at
   sessionstart via the `SuiteConfig.from_yaml` `FileNotFoundError` catch.
2. **One suite per session is already the invariant** — sessionstart loads
   exactly one suite and enumerates its combos. This feature changes how
   that one suite is *chosen*, not how many run.
3. **Precedent for regex semantics exists**: sweep values use `fullmatch`
   against the candidate set, with expansion recorded in `run.yaml`
   (`design/feat/20260716-1647-exhaustive-maccity.md`). The selector follows
   the same fullmatch convention.
4. **`.env` machinery is already available**: pydantic-settings 2.14 (with
   `python-dotenv` as a hard dependency) supports
   `SettingsConfigDict(env_file=...)`; matching is case-insensitive by
   default, so the requested lowercase `cece_root_dir=` keys work against
   the `CECE_` prefix. No new dependency.
5. **Subprocess harness tests run with `cwd=` the repo root**
   ([test_dry_run.py](src/tests/ufs_chem_assay/test_dry_run.py),
   [test_root_dir_guards.py](src/tests/ufs_chem_assay/test_root_dir_guards.py)),
   and in-process tests construct `Settings()` from the same cwd. Once a
   real `.env` lives at the repo root, every "no environment" assertion
   would silently absorb it — the tests must move to a neutral cwd.
6. **`.gitignore` is stale** (single monorepo-era entry
   `/combo-test-runner/.venv/` that matches nothing here), and `.env` will
   contain machine-specific absolute paths that must not be committed.

## Design

### Suite selection: regex over discovered suites

`resolve_suite_path` is replaced by `select_suite` in
[resolution.py](src/resolution.py) (pure, pytest-free, unit-testable):

```
select_suite(option: str, search_paths: list[Path]) -> Path
```

- **Escape hatch first**: if `option` names an existing file, that file is
  used verbatim — absolute paths and repo-relative invocations like
  `--suite-config=src/tests/config/suite/exhaustive-maccity-run-only-suite.yaml`
  keep working unchanged.
- Otherwise `option` is compiled as a regex (`re.error` →
  `ValueError`/`UsageError` naming the bad pattern) and matched against the
  **candidate set**: every `**/*.yaml` found recursively under each search
  root, in search-root order.
- **Match rule** (sweep-consistent `fullmatch`): a candidate is selected
  when the pattern fullmatches **its file name** or **its posix path
  relative to its search root**. Filename matching makes the common case
  trivial (`simple-maccity-suite.yaml` is both a literal name and a valid
  regex that fullmatches it); relative-path matching disambiguates
  same-named suites in different roots or subdirectories
  (`nightly/smoke-suite\.yaml`).
- **Exactly one match required.** Zero matches → error listing every
  discovered candidate (relative path + which root); more than one → error
  listing the matches. The same file reachable via duplicate/overlapping
  roots is deduplicated by resolved path before counting.
- Errors raise `ValueError`; sessionstart converts to `pytest.UsageError`
  at the boundary (existing conftest pattern).

### Search paths: multi-directory, built-in root always last

`suite_config_search_path` ([settings.py](src/settings.py)) changes from
`Path | None` to a list:

- Env var name **unchanged** (`CECE_SUITE_CONFIG_SEARCH_PATH`), now
  `os.pathsep`-separated (colon on unix) for multiple directories. Typed
  `list[Path]` with `NoDecode` + a `field_validator` doing the split
  (pydantic-settings would otherwise attempt JSON decoding for complex
  types); described field; default `[]`.
- The **built-in suite directory** (`src/tests/config/suite/`, located
  relative to the source tree, not cwd) is always appended as the final
  search root. Checked-in suites therefore stay selectable everywhere, the
  bare default works with zero configuration, and user roots take
  precedence in listing order. Collisions with checked-in names remain
  resolvable via relative-path patterns.
- `config_search_path` (base driver configs) is untouched.

### Default: `simple-maccity-suite.yaml`, one suite per session

The `--suite-config` default becomes the literal string
`simple-maccity-suite.yaml` — under selector semantics it fullmatches
exactly the checked-in default suite in the built-in root. As suites
accumulate (in-repo or in external search roots), a bare `uv run pytest`
still selects only this suite; running anything else is always an explicit
choice. The one-suite-per-session invariant (audit #2) is unchanged.

### `.env` support

- `SettingsConfigDict` gains `env_file=".env"` (cwd-relative, the dotenv
  convention — running from the repo root picks it up; README documents
  this). Precedence, highest first: `--cece-root-dir` flag (init kwarg) →
  real environment → `.env` → field default. Case-insensitive matching
  accepts the requested lowercase keys.
- A real `.env` is created at the repo root with the two machine-specific
  entries from the requirements (`cece_root_dir=…/git-benkozi/CECE`,
  `cece_baseline_root_dir=…/cece-baselines`), making `uv run pytest`
  integration-ready with no exports — this also resolves the
  baseline-comparison env noted in the portability fix's implementation
  notes.
- `.gitignore` is rewritten: `.env` (machine paths never committed), plus
  replacing the stale monorepo entry with this repo's actual transients
  (`.venv/`, `__pycache__/`, already-untracked caches).

### Test-harness consequence: neutral cwd (audit #5)

Every test that asserts environment-free behavior must be insulated from
the repo-root `.env`:

- The subprocess helpers in `test_root_dir_guards.py` and
  `test_dry_run.py` switch to `cwd=tmp_path` with **absolute** test-file
  paths (pytest resolves conftest from the test path's rootdir, so
  collection is cwd-independent).
- `test_settings.py`'s env-scrubbing fixture additionally
  `monkeypatch.chdir(tmp_path)` so in-process `Settings()` construction
  never reads the repo `.env`.

## TDD plan (red first)

- `select_suite` unit tests (tmp-dir trees, no pytest machinery):
  - literal filename selects the one match; nested files found
    recursively; multiple roots searched with dedup of overlapping roots.
  - relative-path fullmatch disambiguates two same-named suites in
    different roots; filename-only pattern matching both → error listing
    exactly the two matches.
  - zero matches → error listing every candidate with its root; invalid
    regex → error naming the pattern; existing-file escape hatch bypasses
    the search (file need not live under any root).
- `Settings` tests: `CECE_SUITE_CONFIG_SEARCH_PATH=a:b` → `[Path("a"),
  Path("b")]`; single value still works; unset → `[]`.
- `.env` tests (tmp cwd): `cece_root_dir` in `.env` populates
  `Settings().root_dir`; a real env var beats the `.env` value; an init
  kwarg beats both.
- Harness subprocess tests, from a neutral cwd: bare `--dry-run` with no
  environment and no `.env` still passes; a `--suite-config` regex
  matching nothing → `UsageError` listing candidates; the exhaustive suite
  selected **by filename** (`--suite-config=exhaustive-maccity-run-only-suite.yaml`,
  no path) passes `--dry-run`.
- Existing guard/dry-run subprocess tests stay green after the
  neutral-cwd move (their assertions unchanged).

Integration: `uv run pytest src/tests/test_driver_combos.py` from the repo
root with **only `.env`** supplying `root_dir` and `baseline_root_dir` —
the standing `simple-maccity-suite.yaml` real-driver run, now export-free.

## Acceptance criteria

- Bare `uv run pytest` runs only `simple-maccity-suite.yaml`, however many
  suite files exist under the search roots.
- `--suite-config` accepts a regex; it must fullmatch exactly one
  discovered suite's filename or root-relative path; zero/many matches
  and invalid patterns fail fast with candidate/match listings; an
  existing file path is used verbatim.
- `CECE_SUITE_CONFIG_SEARCH_PATH` accepts multiple colon-separated
  directories, searched recursively, with the built-in suite directory
  always available as the final root.
- `.env` at the repo root supplies `cece_root_dir` and
  `cece_baseline_root_dir`; flag > env > `.env` precedence holds; the file
  is gitignored and populated on this machine with the two required
  values.
- All suites pass `--dry-run`; harness suite green without docker from a
  neutral cwd; the `simple-maccity-suite.yaml` integration run passes with
  configuration coming from `.env` alone.

## Implementation notes

- Implemented as designed; no deviations. `select_suite` lives in
  `resolution.py` (with `resolve_suite_path` removed), the search-path
  split validator uses `NoDecode`, and the built-in suite directory is
  appended as the final root in `pytest_sessionstart`.
- `.env` created with the two machine-specific values and gitignored; the
  stale monorepo-era `.gitignore` entry replaced with this repo's actual
  transients.
- Verified: harness suite green (147 tests, subprocess tests from neutral
  cwds); exhaustive suite selected **by filename** passes `--dry-run`
  (1440 skips) with no environment; the `simple-maccity-suite.yaml`
  integration run (18/18, real docker) passes with configuration from
  `.env` alone — no exports.
