## Goal

Give the harness one small, self-contained way to move data between a local directory and a **private** S3 prefix, and prove it works end to end:

1. **A wrapper around `aws s3 sync`** (`src/s3_sync.py`): one pydantic configuration object in, exactly one `aws s3 sync` subprocess call per invocation, a result object out. Sync is the primitive because it is reentrant — an interrupted multi-gigabyte transfer resumes by re-running the same command, and unchanged files are skipped.
2. **A `pydantic-settings` object for the AWS environment** (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, optional `AWS_SESSION_TOKEN`, `AWS_DEFAULT_REGION`), validated at call time so a missing credential is a named error before any process starts, and handed to the child process explicitly.
3. **Mock tests that always run** (in `src/tests/ufs_chem_assay`, no network, no `aws` binary needed) covering the settings object, the configuration model, the exact argv, the environment the child sees, success/failure/timeout, and the single-call guarantee.
4. **One live test marked `data_integration`** that authenticates to the private test bucket — always `arn:aws:s3:::ufs-chem` (`s3://ufs-chem`), fixed in the test rather than configured — uploads a unique file, downloads it back, asserts byte equality, proves idempotence, and empties its own prefix. Skipped by default (deselected unless `-m data_integration` is given); run by hand in the toolchain container and on Ursa before this merges.
5. **Isolation from the rest of the library**: the module imports nothing from the harness except its logger, so it can be lifted into another repository by changing one line. Wiring it into application data staging and baseline retrieval is future work (recorded below), not this issue.

Out of scope: a CLI subcommand, the run-config `data:` stage, baseline retrieval from S3, a CI job that talks to S3, public (`--no-sign-request`) buckets, S3-to-S3 copies.

## Pre-design audit (fresh facts, 2026-10-06)

Verified on `feature/basic-s3-auth` at `63f0839` (`0.1.0-rc.2`), the live GitHub repositories, and the web where noted.

1. **Nothing in the repository talks to S3 today.** No `boto`, `aws`, or `s3` references in `src/`, `pyproject.toml`, `uv.lock`, or the workflows. Example input data reaches the CECE checkout through CECE's own `examples/download-example-data.py` (public HTTPS, invoked by `applications/cece/examples.py` and by the CLI's data stage); baselines are local directories keyed by ULID, and `integration.yaml` runs with `ASSAY_ENABLE_BASELINE_COMPARISONS=false` because "the baseline store has no public home yet". The issue's second sentence — the S3 connection will serve application data and baseline verification — is the eventual home for both; this design builds the primitive only.
2. **No `aws` binary anywhere the harness runs today.** The toolchain image (`Dockerfile`: `ghcr.io/astral-sh/uv:python3.14-bookworm-slim` + `git` + `g++`) has none; this Mac has none (`aws not found`); Ursa could not be reached from here (hostname unresolvable), so its state is unverified — the login node may or may not carry one. GitHub's `ubuntu-latest` runners ship AWS CLI v2 preinstalled.
3. **AWS CLI v1 is in maintenance mode.** AWS announced that v1 (the PyPI `awscli` package, 1.46.1 at refinement time) entered maintenance mode on 2026-07-15 — critical fixes only — and reaches end of support on 2027-07-15, recommending migration to v2. v2 (2.37.10) is distributed as a standalone zip installer per architecture (`x86_64`, `aarch64`), bundles its own interpreter, and is not on PyPI. The `s3 sync` subcommand and the flags this design uses (`--dryrun`, `--delete`, `--exclude`, `--include`, `--no-progress`, `--only-show-errors`) are identical across v1 and v2.
4. **AWS credential and configuration mechanics.** The CLI resolves credentials in order: command-line/env (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`) before profile files, so explicit env keys win over any ambient `AWS_PROFILE`. `AWS_DEFAULT_REGION` sets the region. `AWS_CONFIG_FILE` relocates the config file for one process. The S3 transfer settings (`max_concurrent_requests`, `multipart_chunksize`, …) exist only in that config file — there is no environment variable for them — which is why AQM-Eval reaches for `aws configure set` (a write to the user's `~/.aws/config`, reset afterwards).
5. **`aws s3 sync` semantics that this design leans on.** Sync copies files whose size or modification time differ between source and destination and skips the rest, so re-running an interrupted transfer continues it; `--delete` removes destination objects absent from the source — with an empty source directory it empties the destination prefix (web-confirmed; the standard caution applies); `--exclude`/`--include` filters are evaluated in the order given, so "exclude everything, then include these" is the idiom; `--dryrun` lists the operations and moves nothing; `--no-progress` keeps the per-file `upload:`/`download:` lines and drops the progress bar, which is what a captured log wants.
6. **pydantic-settings is already in place**, with two conventions to mirror or deliberately break: `settings.Settings` and `applications.base.ApplicationSettings` are frozen, `extra="ignore"`, case-insensitive, and read the cwd `.env`; the harness tests scrub ambient variables with `monkeypatch` and `chdir` to `tmp_path` so the repo `.env` is out of scope (`test_settings.clean_env`); every process call in the harness is mocked at the module (`runner.subprocess.check_output`) in the unit tests.
7. **pytest configuration.** `[tool.pytest.ini_options]` registers no markers and no `addopts`; `pythonpath = ["src", ".github/workflows/scripts"]`. `-m` is a single-valued option: one given on the command line replaces one from `addopts`. pytest's `-m` expression grammar accepts `-` inside identifiers and `pytest.mark` builds a decorator for any attribute name, so a marker literally called `data-integration` would be registrable, applicable (`getattr(pytest.mark, "data-integration")` — the hyphen is not valid attribute syntax) and selectable (`-m data-integration`); the user chose `data_integration` (Resolved decisions), so the plain attribute syntax applies. CI's `tests` job runs `uv run pytest src/tests/ufs_chem_assay` inside the image with no environment at all.
8. **The reference, distilled** (`AQM-Eval` `data_sync/core.py`): a pydantic `AbstractContext` (`dst_dir`, `s3_root`, `max_concurrent_requests`, `dry_run`) subclassed per dataset; a generic `AbstractS3SyncRunner[T]` whose `_create_sync_cmd_` builds `aws s3 sync --no-sign-request [--dryrun] --exclude * --include … <s3_root> <dst_dir>`; `run()` sets `max_concurrent_requests` globally with `aws configure set`, `check_call`s the command (output not captured), and resets the setting in `finalize()`; a `typer` CLI wraps it. Its tests are dry runs of the real binary and an exact argv match. What transfers here: one config object, the exclude-then-include idiom, `max_concurrent_requests` as a config knob, dry run as a first-class field, an exact-argv test. What does not: `--no-sign-request` (our bucket is private), the global `aws configure set` (replaced by a per-process config file), the per-dataset subclass tree (premature), `typer` (not a dependency; no CLI in scope), uncaptured output.
9. **Ursa network shape** (runbook): login nodes have network and are where downloads run; compute nodes are network-restricted. Any future S3 sync therefore belongs in the data stage on the login node, never inside a driver job — the live test runs on the login node, like step 5 of the runbook.
10. **Repository secrets could not be listed** (HTTP 403 with the available token), so whether AWS credentials already exist as secrets is unknown. The issue asks for the authenticated test to be run in the container and on Ursa before merging — by hand — and for the mock tests to run always; it does not ask for a CI job, and none is designed (Decisions; a secrets-gated job is Future work).

## Design

### 0. Decisions

- **AWS CLI v2 is an external tool prerequisite**, like `docker`, `git`, and `sbatch` — not a Python dependency (audit facts 2–3). v1 from PyPI would have been the uv-native choice (it would ride `uv sync` into the image, Ursa, and CI with no install step), but it is in maintenance mode as of this refinement, and v2 is not on PyPI. The wrapper locates `aws` on `PATH` (overridable per config object) and fails with an install hint when it is absent. The toolchain image installs v2; the runbook gains a user-local install step for Ursa; laptops use their package manager; GitHub runners already have it. Confirmed by the user (Resolved decisions); the v1 alternative is recorded there.
- **The module is isolated**: `src/s3_sync.py` imports `logs.get_logger` and nothing else from the harness (its own frozen, `extra="forbid"` models are declared inline rather than inheriting `models.base.StrictModel`, so there is no second import). Moving it elsewhere is one line (`logging.getLogger(__name__)`). The harness logger is kept because the always-do list prefers it and `ASSAY_LOG_LEVEL` then governs the wrapper's output.
- **Credentials come from the environment only — never from `.env`.** `AwsEnvironment` sets no `env_file`. The harness `.env` carries per-machine paths; long-lived access keys in a plain file beside the checkout is a worse habit than the AWS-standard environment, and the tests must be able to prove a `.env` is ignored. Confirmed by the user (Resolved decisions).
- **Secrets never appear in argv or logs.** Keys are `SecretStr` fields; they reach the child only through its environment (`subprocess_env`), the command line carries URIs and flags only, and the logger prints argv — asserted by a test that scans `caplog` for the secret values.
- **Per-process AWS config instead of `aws configure set`** (audit fact 4, reference contrast in fact 8). When `max_concurrent_requests` is set, the wrapper writes a throwaway config file (`[default]`, then the nested `s3 =` block with `max_concurrent_requests = N` indented on its own line — the CLI's config syntax for S3 transfer settings) in a `TemporaryDirectory` and points `AWS_CONFIG_FILE` at it for that one call. Nothing in the user's home directory is touched.
- **Dry run tunnels straight into `aws s3 sync --dryrun`.** `S3SyncConfig.dry_run=True` adds the flag and nothing else changes: same argv otherwise, same credentials, same single call, same `S3SyncResult` (its `dry_run` field set). The CLI then prints one `(dryrun) upload: … to …` / `(dryrun) download: …` / `(dryrun) delete: …` line per operation it would perform and moves nothing — that output *is* the plan, so `sync()` logs a dry run's output at INFO (a real run's at DEBUG) and returns it verbatim in `result.output` for callers to inspect. No wrapper-side simulation: what you see is what the binary would do, filters and all.
- **`sync()` is exactly one `subprocess.run`.** No pre-flight `aws` calls, no retries, no post-processing calls: the issue's "each call to the wrapped sync command executes a single call to `aws s3 sync`" is a tested invariant (`subprocess.run` called once with the expected argv).
- **Deleting a test prefix is also a sync**: `aws s3 sync <empty-dir> s3://…/<prefix>/ --delete` (audit fact 5). It keeps "sync is the only verb" literally true and makes `delete` an explicit field. Two guards: `delete=True` is refused when the S3 side has no key prefix (a bucket root can never be emptied through this wrapper), and the live test's prefix is a fresh ULID under the constant `s3://ufs-chem/ufs-chem-assay-tests/`.
- **Marker spelled `data_integration`** (user decision, 2026-10-06; the issue's hyphenated spelling would have worked too — audit fact 7 — but the underscore keeps the conventional `pytest.mark.data_integration` syntax), registered in `pyproject.toml` with `--strict-markers`, and **skipped by default**, realized as deselection: `addopts = ["-m", "not data_integration"]` keeps it out of `uv run pytest` and CI's `tests` job (the summary reads `1 deselected`), and `-m data_integration` on the command line replaces the default and runs only the live test. When selected, missing credentials **fail** (pydantic `ValidationError` naming the variable) rather than skip — a live run that silently skips would be worse than no run.
- **The `ufs-chem-assay-tests/` prefix** under the bucket is this refinement's choice, confirmed by the user.
- **No CI job against S3 in this change** (audit fact 10): the issue's acceptance is a by-hand run in the container and on Ursa, listed under Verification with exact commands. A secrets-gated job is Future work.
- **The test bucket is a constant: `arn:aws:s3:::ufs-chem`** (user direction, 2026-10-06). The live test always targets `s3://ufs-chem/ufs-chem-assay-tests/<ULID>/`; there is no `ASSAY_S3_TEST_URI` and no settings object for the target. The bucket ARN and the `ufs-chem-assay-tests/` prefix are module constants in the test (`TEST_BUCKET_ARN`, with the `s3://` URI derived from it by stripping `arn:aws:s3:::`), so changing the bucket is a one-line edit with a conventional-commit trail, not a per-machine variable. Credentials remain the only environment input.
- **Local sides are directories, S3 sides are `s3://` URIs, at least one side is S3.** S3-to-S3 is refused (out of scope; `aws s3 sync` would allow it). A local source must exist; a local destination is created by `aws` itself.

### 1. `src/s3_sync.py` — the module

```python
"""One `aws s3 sync` per call, configured by a pydantic model, credentials from
the environment. Stand-alone on purpose: the harness logger is the only harness
import (one line to replace when this module is reused elsewhere)."""

S3_URI_PATTERN = r"^s3://[a-z0-9][a-z0-9.-]{1,61}[a-z0-9](/.*)?$"   # bucket rules; optional key prefix
S3Uri = Annotated[str, StringConstraints(pattern=S3_URI_PATTERN)]
_AWS_ENV_NAMES = ("AWS_ACCESS_KEY_ID", "AWS_SECRET_ACCESS_KEY", "AWS_SESSION_TOKEN", "AWS_DEFAULT_REGION")


class AwsEnvironment(BaseSettings):
    """The standard AWS variables, read from the environment at construction
    (never from .env); a missing key is a ValidationError naming it."""
    # no env_prefix, no env_file; env_ignore_empty: an exported-but-empty
    # variable counts as missing, not as a blank credential
    model_config = SettingsConfigDict(frozen=True, extra="ignore", env_ignore_empty=True)

    aws_access_key_id: SecretStr = Field(min_length=1, description="AWS_ACCESS_KEY_ID; required")
    aws_secret_access_key: SecretStr = Field(min_length=1, description="AWS_SECRET_ACCESS_KEY; required")
    aws_session_token: SecretStr | None = Field(None, description="AWS_SESSION_TOKEN; temporary credentials only")
    region: str = Field(
        "us-east-1",
        validation_alias=AliasChoices("AWS_REGION", "AWS_DEFAULT_REGION"),
        description="The bucket's region: AWS_REGION, else AWS_DEFAULT_REGION, else us-east-1",
    )

    def subprocess_env(self, base: Mapping[str, str]) -> dict[str, str]:
        """A copy of `base` with the credentials and region overlaid under
        both region names (AWS_REGION wins in the CLI, so both are set),
        an ambient AWS_SESSION_TOKEN dropped when this object has none,
        and AWS_PROFILE dropped (explicit keys never go through a profile) —
        the only place the secrets are revealed."""


class S3SyncConfig(BaseModel):
    """One sync: where from, where to, and how. Frozen, unknown keys rejected."""
    model_config = ConfigDict(frozen=True, extra="forbid")

    # union_mode left_to_right: a string is an S3 URI when it matches the
    # pattern, otherwise a local path; local paths are resolved to absolute
    # at validation so argv and logs never depend on the caller's cwd
    source: S3Uri | Path = Field(union_mode="left_to_right", description="s3://bucket/prefix or an existing local directory")
    destination: S3Uri | Path = Field(union_mode="left_to_right", description="s3://bucket/prefix or a local directory (created by aws)")
    dry_run: bool = Field(False, description="--dryrun: list the operations, move nothing")
    delete: bool = Field(False, description="--delete: remove destination files absent from the source; refused on a bucket root")
    only_show_errors: bool = Field(False, description="--only-show-errors: no per-file lines (large transfers); refused with dry_run, whose lines are the point")
    exclude: list[str] = Field(default_factory=list, description="--exclude patterns, applied first")
    include: list[str] = Field(default_factory=list, description="--include patterns, applied after exclude")
    max_concurrent_requests: int | None = Field(None, gt=0, description="s3.max_concurrent_requests for this call, via a throwaway AWS_CONFIG_FILE; None keeps the CLI default (10)")
    timeout_s: int | None = Field(None, gt=0, description="subprocess timeout; None waits indefinitely")
    aws_executable: str = Field("aws", description="The AWS CLI to run; resolved on PATH")

    # validators: at least one S3 side, never two; a local source is an existing
    # directory (a file is rejected); local sides resolved absolute; delete requires a
    # non-empty key prefix on every S3 side ("s3://bucket" and "s3://bucket/" both count
    # as the root); only_show_errors and dry_run are mutually exclusive.

    @property
    def argv(self) -> list[str]:
        """[aws, s3, sync, <source>, <destination>, --no-progress,
        --dryrun?, --delete?, --only-show-errors?, --exclude P…, --include P…] —
        flags after the positionals, exclude before include (aws evaluates
        filters in order). argv[0] is aws_executable as given; sync() swaps in
        the path shutil.which resolved."""


class S3SyncResult(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")
    argv: list[str] = Field(description="The command that ran, as executed")
    returncode: int = Field(description="aws exit status (0 on success)")
    output: str = Field(description="Combined stdout+stderr of the call")
    dry_run: bool = Field(description="Whether the call was a --dryrun")


def sync(config: S3SyncConfig, aws: AwsEnvironment | None = None) -> S3SyncResult:
    """Run one `aws s3 sync`. `aws` defaults to AwsEnvironment() (the
    environment at call time). Raises FileNotFoundError (aws not on PATH,
    with the install hint), ValidationError (credentials), CalledProcessError
    (nonzero exit, output attached), TimeoutExpired (timeout_s)."""
```

Behaviour of `sync()`, in order: resolve `aws` with `shutil.which(config.aws_executable)` (absent → `FileNotFoundError` whose message names the executable and points at the README's install section; present → the resolved absolute path becomes argv[0], so what ran is unambiguous in the result and the log); construct `AwsEnvironment()` when none is given; build the child environment from `os.environ` through `subprocess_env`; when `max_concurrent_requests` is set, write the config file into a `TemporaryDirectory` and set `AWS_CONFIG_FILE` in that environment; log the argv at INFO (and "DRY RUN" when `dry_run`) — the child environment is never logged at any level; `subprocess.run(argv, env=env, stdout=PIPE, stderr=STDOUT, timeout=config.timeout_s, check=False)`; on nonzero exit log the output at ERROR and raise `CalledProcessError(returncode, argv, output)`; on success log the output at DEBUG — at INFO when `dry_run`, since the listed operations are the point of a dry run — and return the result. The temporary directory lives for the duration of the call only.

Typing: no `Any`; `disallow_untyped_defs` holds; `mypy` already covers `src/`.

### 3. Tests — `src/tests/ufs_chem_assay/test_s3_sync.py`

A `clean_aws_env` fixture scrubs the AWS variables (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `AWS_REGION`, `AWS_DEFAULT_REGION`, `AWS_PROFILE`, `AWS_CONFIG_FILE`) and `chdir`s to `tmp_path` (the `test_settings` pattern); the mock tests request it, the live test must not (it needs the real variables); the module-level `hermetic_platform` autouse fixture already applies. `subprocess.run` is patched at `s3_sync.subprocess.run` and `shutil.which` at `s3_sync.shutil.which` (`pytest-mock`), as `test_runner.py` does for the driver.

**Mock tests (always run):**

- `AwsEnvironment`: missing keys → `ValidationError` whose message names `aws_access_key_id` and `aws_secret_access_key`; both present → populated, `repr()`/`str()` show `**********`, `get_secret_value()` returns the value; lowercase/uppercase variable names both work; session token optional; region defaults to `us-east-1`, follows `AWS_DEFAULT_REGION`, and `AWS_REGION` wins when both are set; an exported-but-empty `AWS_ACCESS_KEY_ID` is a `ValidationError` (not a blank credential); a `.env` in cwd carrying the keys is **ignored** (still a `ValidationError`); `subprocess_env` returns a copy with the credentials and both region names overlaid, drops an ambient `AWS_SESSION_TOKEN` when the object has none, drops `AWS_PROFILE`, leaves the base mapping untouched, and keeps unrelated keys (`PATH`, `HOME`, proxies).
- `S3SyncConfig`: local→S3 and S3→local accepted; local→local and S3→S3 rejected with messages naming the rule; bucket-name pattern (uppercase, too short, trailing dot rejected; a prefix with slashes accepted); a string local path becomes an absolute `Path` (relative input resolved against cwd); a nonexistent local source rejected, a *file* as local source rejected, a nonexistent local destination accepted; `delete=True` with `s3://bucket` and with `s3://bucket/` (no prefix either way) rejected, with `s3://bucket/prefix` accepted; `only_show_errors=True` with `dry_run=True` rejected; `max_concurrent_requests=0` and `timeout_s=0` rejected; unknown keys rejected; instances frozen.
- `argv`: exact list for the plain case; `--dryrun`, `--delete`, `--only-show-errors`, `--exclude`/`--include` ordering (every exclude before every include, each as its own `--flag value` pair); `aws_executable` honoured.
- `sync()` success: `subprocess.run` called **once**; `args[0][0]` is the path `shutil.which` returned and `args[0][1:] == config.argv[1:]`; `kwargs["env"]` carries the overlaid variables and nothing secret is in `args`; `stderr is subprocess.STDOUT`; `timeout` forwarded; result carries argv/returncode/output/dry_run; `caplog` at DEBUG contains the argv line and never the secret values.
- `sync()` with `max_concurrent_requests`: the child env has `AWS_CONFIG_FILE` pointing at a file that, read during the mocked call (a `side_effect` that captures the file's text), contains `[default]`, an `s3 =` line, and an indented `max_concurrent_requests = 3`; without the knob `AWS_CONFIG_FILE` is absent from the child env (unless the caller's environment already carried one, which is preserved); the temporary directory is gone after the call.
- `sync()` dry run: argv ends with `--dryrun` in the mocked call; the mock's output (`(dryrun) upload: up/probe.txt to s3://ufs-chem/…/probe.txt`) comes back verbatim in `result.output`, `result.dry_run` is true, and `caplog` shows it at INFO (a non-dry-run's output appears only at DEBUG).
- `sync()` failure: returncode 1 → `CalledProcessError` with `.output` = captured text and `.cmd` = argv, logged at ERROR; `TimeoutExpired` raised by the mock propagates; `shutil.which` → None → `FileNotFoundError` mentioning `aws` and the README, and `subprocess.run` never called.
- Round trip under mock: an upload config and a download config built from the test bucket URI (`s3://ufs-chem/ufs-chem-assay-tests/<ulid>/`, derived from `TEST_BUCKET_ARN`) produce two `sync` calls and two `subprocess.run` calls — the pattern the live test uses, exercised without network.

**Live test (`data_integration`, skipped by default through deselection):**

```python
@pytest.mark.data_integration
def test_private_bucket_round_trip(tmp_path: Path) -> None:
```

- Target: `TEST_BUCKET_ARN = "arn:aws:s3:::ufs-chem"` and `TEST_PREFIX = "ufs-chem-assay-tests"`, constants in the test module; the URI `s3://ufs-chem/ufs-chem-assay-tests` is derived from the ARN (a small helper the mock tests also cover: `arn:aws:s3:::name[/key]` → `s3://name[/key]`, anything else → `ValueError`). Credentials come from `AwsEnvironment()`; missing → `ValidationError` (fail, not skip).
- prefix = `s3://ufs-chem/ufs-chem-assay-tests/<ULID>/`; `up/` holds `probe.txt` (the ULID and a timestamp) and `nested/second.bin` (a few KiB of random bytes) so the tree, not just one object, round-trips.
- `sync(up → prefix, dry_run=True)` first: nothing is written, and the output names both files as `(dryrun) upload:` lines — the plan, logged at INFO so a `-s` run shows what is about to happen.
- `sync(up → prefix)`; `sync(prefix → down/)`; assert the relative file set and bytes are identical.
- `sync(up → prefix)` again: output contains no `upload:` line (unchanged files skipped — the reentrancy property in one assertion).
- `finally`: `sync(empty/ → prefix, delete=True, dry_run=True)` shows the `(dryrun) delete:` lines for exactly the uploaded objects, then `sync(empty/ → prefix, delete=True)`, then `sync(prefix → check/)` yields no files (`aws` creates no directory when nothing downloads, so the assertion is "absent or empty") — the prefix is gone, and the test leaves nothing behind even when an assertion failed mid-way. The cleanup is best-effort: a failure inside the `finally` is logged and raised only when the body itself passed, so a credentials or upload failure is never masked by the cleanup's own failure.
- Preconditions beyond the environment: the `aws` CLI on `PATH`; credentials whose policy grants `s3:ListBucket` on `arn:aws:s3:::ufs-chem` and `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` on `arn:aws:s3:::ufs-chem/ufs-chem-assay-tests/*` (the least the round trip needs; broader grants work too).

### 4. `Dockerfile` — AWS CLI v2 in the toolchain image

After the `apt-get` layer: `curl`, `ca-certificates` (explicit — the image installs with `--no-install-recommends`, so `curl` alone would not pull the CA bundle), and `unzip` added to the package list, then

```dockerfile
# AWS CLI v2 (s3_sync.py shells out to `aws s3 sync`); v1 on PyPI is in
# maintenance mode. Architecture-aware: the official zip per uname -m.
RUN curl -fsSL "https://awscli.amazonaws.com/awscli-exe-linux-$(uname -m).zip" -o /tmp/awscliv2.zip \
    && unzip -q /tmp/awscliv2.zip -d /tmp \
    && /tmp/aws/install --bin-dir /usr/local/bin --install-dir /usr/local/aws-cli \
```

### 7. Edge cases and guards (consistency scan, 2026-10-06)

Found by re-reading the design against the CLI's documented behaviour; each is handled in the sections above and listed here so the implementation checks every one.

- **An ambient `AWS_PROFILE`** naming a profile that the (throwaway or real) config file lacks makes the CLI fail with "config profile could not be found" even when env keys are present. `subprocess_env` drops `AWS_PROFILE`: explicit keys never resolve through a profile.
- **`AWS_REGION` beats `AWS_DEFAULT_REGION`** in CLI v2. The settings object reads both (`AWS_REGION` first) and the child env carries both names, so an ambient `AWS_REGION` can never silently redirect a call.
- **Exported-but-empty variables** (`export AWS_SESSION_TOKEN=`; a `docker run -e VAR` pass-through of an empty host value) would otherwise validate as blank credentials: `env_ignore_empty=True` plus `min_length=1` make them "missing".
- **A stale ambient `AWS_SESSION_TOKEN`** paired with long-lived keys fails authentication; `subprocess_env` removes it when the settings object has none.
- **The throwaway `AWS_CONFIG_FILE` replaces the user's whole config** for that call (any `ca_bundle`, `s3.endpoint_url`, or proxy settings they keep there are not seen); proxies set in the environment (`HTTPS_PROXY`, what Ursa would use) are unaffected because the child env is a copy of `os.environ`. Documented on the field.
- **`s3://bucket/` is a bucket root**, like `s3://bucket`: the `delete` guard strips a trailing slash before deciding whether a key prefix exists. S3 URIs are otherwise passed verbatim — `aws s3 sync` treats `prefix` and `prefix/` alike.
- **`delete=True` with a local destination** is allowed (a mirror download legitimately prunes stale local files) and is the second sharp edge after bucket roots: it must only ever point at a harness-owned directory. Recorded under Risks; no future caller should default it on.
- **Relative local paths** would otherwise resolve against the harness's cwd at call time; the model resolves them to absolute at validation.
- **A file given as the local source** is not something `aws s3 sync` accepts; rejected at validation rather than by a CLI error.
- **`only_show_errors` with `dry_run`** would print a plan with no lines; rejected at validation.
- **`shutil.which` and the child's `PATH`**: `subprocess` resolves argv[0] against the *passed* environment's `PATH`; since that is a copy of `os.environ`, the pre-flight `which` and the exec agree, and argv[0] carries the resolved path anyway.
- **Downloading from an absent or emptied prefix** exits 0 with no output and creates no local directory; the live test's final check asserts "absent or empty", not "exists and is empty".
- **A test killed mid-way** (SIGKILL, lost SSH session without tmux) leaves its ULID prefix behind — the `finally` cannot run. Concurrent runs never collide (fresh ULIDs), but abandoned prefixes accumulate; an S3 lifecycle rule expiring `ufs-chem-assay-tests/` objects after a day is the bucket-side guard (operator step, Future work).
- **Timeouts** kill the child (`subprocess.run` semantics) and leave a partial transfer; that is exactly the case sync's reentrancy covers — re-run the same config.
- **Output volume**: `--no-progress` still prints one line per transferred file, which a multi-thousand-file sync turns into a large captured string; `only_show_errors` exists for those callers, and the result's `output` is the only copy (DEBUG logging is opt-in through `ASSAY_LOG_LEVEL`).
- **Idempotence assertion direction**: the second upload is skipped because S3's `LastModified` (upload time) is newer than the local mtime and the sizes match; the test asserts upload idempotence only, never download idempotence, which depends on the CLI setting local mtimes.
- **The `addopts` deselection shows in every pytest summary** (`1 deselected`), including runs of `test_driver_combos.py` and CI; cosmetic, documented in the README line that explains the marker.

## Risks and notes

- **`--delete` is the sharp edge.** It is confined by the model (`delete=True` needs a key prefix on the S3 side) and by the live test's constant `ufs-chem-assay-tests/<ULID>/` prefix; nothing the test does can address the `ufs-chem` bucket root, and the model would refuse it anyway. Future callers that sync downloads should leave `delete` at its default; with a local destination it prunes local files, so it is only ever pointed at a harness-owned directory (section 7).
- **The aws CLI is a moving external tool**: the image pins nothing (the installer fetches the current v2), so a v2 release could in principle change output text the live test greps (`upload:`). The assertion is on a stable, documented line; if it drifts, the idempotence check becomes "second run's output is empty of transfer lines" in the same spirit.
- **Ursa's `aws` is unverified** (audit fact 2). If the login node has one on `PATH` or in a module, the runbook step is "check first"; if its version is v1 the wrapper still works (same flags), and the maintenance-mode concern is the site's, not ours.
- **Credentials in the shell history**: the Ursa command exports keys inline for brevity; the README will recommend sourcing them from a mode-600 file outside the checkout instead. Nothing in this design reads `~/.aws/credentials` explicitly, but the CLI still will when the env keys are absent — `AwsEnvironment` requires them, so the wrapper never silently falls through to a profile.
- **Region**: a bucket in another region with the default `us-east-1` fails with a redirect error from the CLI (`PermanentRedirect`), surfaced as a `CalledProcessError` with the output attached — set `AWS_DEFAULT_REGION`.
- **Compute nodes have no network** (audit fact 9): the future data stage must run the sync on the login node before jobs are submitted, exactly where the runbook already downloads CECE's example data.
- **Abandoned test prefixes**: a killed live run leaves `ufs-chem-assay-tests/<ULID>/` behind (section 7); harmless to correctness, tidied by a bucket lifecycle rule (Future work).
- **Image size** grows with the v2 install; the `build` job's gha cache absorbs it after the first run.
