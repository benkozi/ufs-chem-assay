# Feature: output upload — a run's whole output root goes to `s3://ufs-chem/assay-output/<run ULID>/` through the S3 wrapper, comes back by ULID, and a session flag (off by default) does it at session end

Refined 2026-10-23 from the requirements below (no GitHub issue; the user's own five bullets): reuse the S3 syncing utility for output, not only baselines; a dedicated upload utility targeting `<ufs-chem S3 root>/output/<ULID>` (renamed `assay-output/` by the user the same day); a download utility by ULID for ease of use and testing; a harness-run flag that uploads automatically when enabled, off by default; dry runs throughout. Built on the baseline publishing machinery (`design/feat/20261008-1433-baseline-sync/`: the wrapper, the store setting and its validator, the session-end hook that never fails the session, the post-hoc subcommand over a finished output root) and on the output root as the benchmarking work left it (`20261023-0847-add-benchmarking.md`: `benchmarks.csv` at the root and per combination).

## Goal

1. **`ufs-chem-assay upload-output --output-root <root> [--store <s3 prefix | dir>] [--dry-run]`** — the finished output root, as it stands, to **`<output store>/<run_id>/`** with one `aws s3 sync` through `src/s3_sync.py`: `run.yaml`, `combos.csv`, `test-report.csv`, `benchmarks.csv`, the session-level stats and comparison CSVs, and every combination directory (generated config, job script, `.out`, driver log, NetCDF, stats, comparison CSV, plots, GIFs, `baseline.yaml` when published, `benchmarks.csv`). The run ULID is the name — the one identity every artifact already carries — and the default store is `s3://ufs-chem/assay-output` (`ASSAY_OUTPUT_STORE`), the `assay-output/` prefix beside `baselines/` in the same bucket. Re-running the upload resumes it: sync is reentrant, so nothing is refused and nothing is deleted.
2. **`ufs-chem-assay download-output --ulid <run_id> --dest <dir> [--store …] [--dry-run]`** — `<store>/<run_id>/` back to `<dest>/<run_id>/` (`--dest` is required: a download lands where it was asked to, never silently in the cwd), one sync, refused with a clear message when the store holds nothing under that ULID. The round trip is the test: upload a root, download it elsewhere, compare.
3. **A session flag, off by default** — `pytest --upload-output`, the run config's `harness.upload_output: false`, uploads the output root **last** at session end, after the report, benchmarks, publish, stats and plots, so what lands in the bucket is the complete root; it never raises into pytest and names the post-hoc command on failure. With an S3 store the session refuses the flag at start when the bucket is unreachable (a compute node), exactly as `--publish-baselines` does. A dry-run session uploads nothing (there is nothing to keep) and says so.
4. **Dry runs everywhere** — both subcommands pass `--dry-run` through to the wrapper's `--dryrun`, whose `(dryrun) upload:`/`download:` lines are the plan, logged at INFO; a directory store logs the file count it would copy.
5. **An `upload.yaml` record in the root**, written before the sync and uploaded with it: the run ULID, the store and destination, when and by whom, the file count and bytes — the download side reads it to confirm what it got, and a root that carries one says it was uploaded. Like `baseline.yaml`, it is the only thing the upload adds to the root.

## Pre-design audit (fresh facts, 2026-10-23)

Read from the harness checkout at `66cbe5a` ("published baselines"; the global-anthropogenic feature's branch).

1. **The wrapper** (`src/s3_sync.py`): `S3SyncConfig(source, destination, dry_run, delete, exclude, include, no_sign_request, profile, only_show_errors, timeout_s)` — exactly one side an `s3://` URI; `sync()` is one subprocess call returning `S3SyncResult(argv, returncode, output, dry_run)`; `delete` is refused on a bucket root; `only_show_errors` and `dry_run` exclude each other; `check_reachable(uri)` is the credential-free TCP probe. Credentials are the CLI's. `S3_URI_PATTERN` admits a bucket with an optional key prefix.
2. **How baselines use it** (`src/baselines/`): `Settings.baseline_store` (`ASSAY_BASELINE_STORE`, default `s3://ufs-chem/baselines`) with a validator that normalises an S3 prefix (no trailing slash, never a bucket root) or resolves a directory; `store.is_s3`/`location(store, ulid)`; `publish._upload` syncs one combination directory with `only_show_errors=not dry_run, dry_run=dry_run`, or `copytree`s to a directory store, or logs a file count under a directory-store dry run; `_prefix_occupied` probes with a `--dryrun` download into an empty directory (append-only refusal — a property of baselines, not wanted for output re-uploads); `stage._sync_into` is the download: a sync into `<root>/.staging/<ulid>` moved into place only when it holds NetCDF, because `aws s3 sync` of an absent prefix exits 0 and downloads nothing. The CLI subcommand `publish-baselines` reads `run.yaml`, builds `Settings` with the `--store` override as an init kwarg, probes the store, and runs the plan; the session's `--publish-baselines` is refused at `pytest_sessionstart` when `check_reachable` fails, and at session end `publish_session` runs inside `try/except Exception` logging the post-hoc command.
3. **The output root** (a real docker run, `ufs-chem-assay-output-bench/`): `run.yaml`, `combos.csv`, `test-report.csv`, `benchmarks.csv`, `descriptive_stats.csv`, `stats-comparison.csv`, and one directory per combination — 4.6 MB for maccity; a gcafs-anthro root is ≈ 0.6 GB of NetCDF plus plots (its single combination directory is already uploaded as a baseline when published). `run.yaml` carries `run_id`, the identity the user wants the upload keyed by. Nothing in the root records whether it was uploaded.
4. **Session-end order** (`pytest_sessionfinish`): report → benchmarks (per-run, per-combination, committed under the flag) → publish (wrapped) → stats concat and plots → comparison concat and bias plots. Plots are the last artifacts written, so an upload must come after them to be complete.
5. **Run config and stages**: `baselines:` is its own section (`root_dir`, `enabled`, `store`, `atol`, `rtol`), exported as `ASSAY_BASELINE_*` by `_exports`; the pytest flags (`publish_baselines`, `no_suite_update`, `record_benchmarks`) live under `harness:` and render as `--flags`; `SETTINGS_NOT_MIRRORED` lists the settings that live outside `harness:`. `test_harness_section_mirrors_every_setting` pins that set.
6. **The live test** (`test_s3_sync.py::test_private_bucket_round_trip`, `data_integration`): uploads a small tree to `s3://ufs-chem/ufs-chem-assay-tests/<ULID>/`, downloads it, checks bytes, proves the second upload is a no-op, empties exactly that prefix with a `delete=True` sync from an empty directory. The pattern an output round-trip test can copy under its own prefix.
7. **Network on Ursa**: login nodes have it, compute nodes do not; the harness stage runs on the login node under the slurm runtime, so an in-session upload works there; a session inside an allocation must upload post hoc — the same rule as publishing.
8. **Identity and provenance helpers**: `getpass.getuser()`/`socket.gethostname()` for `published_by`, `datetime.now(UTC)`, `baselines.store.digest` — reusable for the upload record.

## Design

### 0. Decisions

1. **The whole root, verbatim, under the run ULID.** `<store>/<run_id>/` mirrors the output root one to one: every file, including per-combination NetCDF and plots and any `baseline.yaml`. No filtering (a run's value for later inspection is all of it — the `.out` of a timed-out job as much as the NetCDF of a passed one), no renaming, no compression (sync skips unchanged files on re-upload, which compression would defeat). A size that becomes a nuisance is the cue for an `exclude` option (Future work), not for a smaller default.
2. **Its own store setting, same shape as the baselines'.** `ASSAY_OUTPUT_STORE` (`Settings.output_store`, default `s3://ufs-chem/assay-output`, the baselines' validator: an `s3://bucket/prefix` never a bucket root, or a local directory), run config `outputs.store`, `--store` on both subcommands. Two stores in one bucket rather than a derived path (`baselines/../assay-output`): each is a setting a user can point elsewhere, and a directory store makes the whole feature testable without AWS.
3. **Upload is resumable, not append-only.** Baselines refuse an occupied prefix because a baseline is immutable; a run's output is the same run every time it is re-uploaded (the ULID is minted once per session), and an interrupted or repeated upload must simply continue — which is what `aws s3 sync` does. No occupancy probe, never `delete`: files removed locally stay in the store, files added (a later `record-benchmarks`? no — that edits the repo; a later `publish-baselines` adds `baseline.yaml` to a combination directory) go up on the next upload.
4. **Download refuses an empty result.** An absent ULID syncs nothing and exits 0; `download-output` checks that `<dest>/<ulid>/run.yaml` arrived (every root has one) and otherwise reports "no output for `<ulid>` under `<store>`", removing the empty directory it created — the `stage._sync_into` pattern with `run.yaml` as the marker.
5. **Last at session end, probed at session start.** The in-session upload is the final step of `pytest_sessionfinish`, inside its own `try/except Exception` that logs `upload-output --output-root=<root>` on failure; `pytest_sessionstart` refuses `--upload-output` with an S3 store when `check_reachable` fails, as for `--publish-baselines`. A `--dry-run` session with `--upload-output` logs that nothing is uploaded and uploads nothing: a dry-run root is reproducible for free.
6. **`upload.yaml`** (`OutputUploadRecord`): `run_id`, `store`, `destination`, `uploaded_at` (UTC), `uploaded_by` (`user@host`), `files` (count), `bytes` (total) — written into the root before the sync (so it is uploaded), rewritten on every upload (the last upload wins; the record is "when this copy was taken"), read by the download to log what came back. Not a per-file digest list: `baseline.yaml` digests a combination because a comparison relies on it; an output copy is for inspection, and the wrapper already verifies transfers.
7. **Generic, one module.** `src/outputs.py`: the record, `upload_output`, `download_output`, with the two transport branches (S3 through the wrapper, a directory by copy) the baselines already have — nothing application-specific; the CLI and the session are thin callers.
8. **No change to `run.yaml`, the benchmark row, or the baseline manifest.** The upload is a transport fact recorded by `upload.yaml`; `run_id` is the join.

### 1. The module — `src/outputs.py`

```python
class OutputUploadRecord(StrictModel):   # upload.yaml
    run_id: str; store: str; destination: str
    uploaded_at: datetime; uploaded_by: str
    files: int; bytes: int

UPLOAD_RECORD = "upload.yaml"

def output_location(store: str, run_id: str) -> str          # <store>/<run_id>/ or <dir>/<run_id> (baselines.store.location)
def upload_output(output_root: Path, store: str, *, dry_run: bool = False) -> OutputUploadRecord
def download_output(run_id: str, store: str, dest: Path, *, dry_run: bool = False) -> Path
```

- `upload_output`: requires `<output_root>/run.yaml` (a root, not any directory; `run_id` read from it and used as the key, never trusted from a directory name); writes `upload.yaml` (dry run: logs the record, writes nothing); S3: `sync(S3SyncConfig(source=output_root, destination=<store>/<run_id>/, only_show_errors=not dry_run, dry_run=dry_run))`; directory store: `copytree(..., dirs_exist_ok=True)` (a re-upload overwrites changed files, like sync), a dry run logs the file count; returns the record. Errors (`CalledProcessError`, `FileNotFoundError` for a missing `aws`, `OSError`) propagate: the callers decide (the CLI's exit 1, the session's log line).
- `download_output`: `target = dest / run_id` (`dest` always given by the caller); S3: sync `<store>/<run_id>/` into a staging directory `dest/.staging/<run_id>` and move into place when `run.yaml` is there, else remove it and raise `ValueError("no output for <run_id> under <store>")`; directory store: `copytree` after checking the source exists; dry run: the wrapper's plan, nothing written, the target path returned anyway. An existing `target` is synced into (resume / refresh), never removed. Returns `target`; logs the record's `uploaded_at`/`files` when `upload.yaml` came along.

### 2. Settings, run config, stages — `settings.py`, `cli/run_config.py`, `cli/stages.py`

- `Settings.output_store: str = Field(DEFAULT_OUTPUT_STORE, …)` with the baseline store's validator generalised (`_store_is_a_prefix_or_directory` applied to both fields); `DEFAULT_OUTPUT_STORE = "s3://ufs-chem/assay-output"`.
- Run config: a new section **`outputs: {store: s3://ufs-chem/assay-output}`** (`OutputsSection`), the flag **`harness.upload_output: false`** (rendered as `--upload-output`); `_exports` adds `ASSAY_OUTPUT_STORE`; `SETTINGS_NOT_MIRRORED` gains `output_store`. The three templates list both keys, false.
- The CLI subcommands build `Settings(output_store=args.store)` when `--store` is given, as `publish-baselines` does with its `--store`.

### 3. The CLI — `cli/main.py`

- **`upload-output --output-root ROOT [--store S] [--dry-run]`**: no `run.yaml` → error exit 1; S3 store → `check_reachable` first (exit 1 naming "a node with network"); then `upload_output`; logs the destination and the record; exit 1 on a transfer error with the wrapper's last output line.
- **`download-output --ulid ULID --dest DIR [--store S] [--dry-run]`**: `--dest` required (argparse); S3 store → `check_reachable`; `download_output`; logs where it landed and what `upload.yaml` says; "no output for …" is exit 1.
- `fetch`, `publish-baselines`, `record-benchmarks` untouched.

### 4. The session — `src/tests/conftest.py`

- `pytest --upload-output` (the option); at `pytest_sessionstart`, with the flag and an S3 `output_store`, `check_reachable` or `UsageError("--upload-output: <reason>; run without the flag and upload afterwards from a node with network: ufs-chem-assay upload-output --output-root=<root>")`.
- At `pytest_sessionfinish`, after the bias plots (the last artifact): if the flag is set and the session was not a dry run, `upload_output(roots.host, settings.output_store)` inside `try/except Exception` → `logger.error("uploading output failed: %s; upload it later: ufs-chem-assay upload-output --output-root=%s")`; a dry-run session logs "dry run: output not uploaded".
- `run.yaml` unchanged; `upload.yaml` appears in the root only when an upload happened.

### 6. Edge cases and guards (consistency scan)

- **A root uploaded, then published**: the later `publish-baselines` writes `baseline.yaml` into a combination directory; a second `upload-output` syncs just that file (and the refreshed `upload.yaml`). Documented as "re-run the upload after publishing if you want the manifest in the copy".
- **A root uploaded twice**: the second sync transfers nothing but the rewritten `upload.yaml`; the record's `uploaded_at` moves — by design (the last copy's time).
- **`clean_root`** removes a previous harness root before a run; the store copy is unaffected — which is the point of uploading.
- **A dry-run session's root** has no `.out`/NetCDF and is never uploaded; `upload-output --output-root` on such a root is allowed (it has `run.yaml`) and uploads the configs and job scripts — harmless, and occasionally useful (sharing what a run *would* do).
- **Download into a non-empty `<dest>/<ulid>`**: sync updates it; nothing local is deleted (no `delete`). A different run's files there would be mixed in — the ULID directory name makes that an unlikely mistake; documented.
- **A directory store** on the same filesystem as the root: `copytree` into `<store>/<run_id>`; `dirs_exist_ok=True` for the re-upload. A dry run logs the count only.
- **Credentials and network**: the CLI's chain, as everywhere; the probe fails fast on a compute node; `--dry-run` still needs network for an S3 store (the wrapper's `--dryrun` lists remote objects).
- **Large roots**: a gcafs-anthro root is ≈ 0.6 GB; `aws s3 sync` streams it; the user's `~/.aws/config` transfer tuning applies, not a harness setting.
- **`upload.yaml` under `--dry-run`** is not written, so a dry run leaves the root byte-identical.
- **Coverage**: the wrapper is mocked as in the baseline tests; a live `data_integration` round trip under `s3://ufs-chem/ufs-chem-assay-tests/<ulid>-output/` (upload a fabricated root, download it beside, compare file lists and bytes, re-upload is a no-op, empty the prefix) joins the existing live test.

## Risks and notes

- **Bucket growth**: every uploaded run is ≈ its NetCDF size; gcafs-anthro ≈ 0.6 GB per run, maccity negligible. Uploading is opt-in per run and never automatic in the templates. Pruning is Future work; the ULID names make "delete everything before <date>" a prefix listing away.
- **Two copies of a published combination** (the baseline under `baselines/<combo_id>/`, the same directory inside `output/<run_id>/`): accepted — different purposes, different lifetimes, and the baseline copy is the immutable one.
- **`aws s3 sync` and symlinks**: the output root contains none (the data links live in the checkout's `data/`, not in the root).
- **Clock and user in `upload.yaml`** are the uploading machine's, as for `baseline.yaml`.
