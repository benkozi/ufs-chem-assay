## 2. The modulefile

The harness has no C7 modulefile yet. This one is the weather model's (`ufs_gaeac7.oneapi.lua` of ufs-community/ufs-weather-model#3432) with the oneAPI swap added and the Kokkos packages loaded only if they exist. Write it under `$ROOT`:

```bash
mkdir -p $ROOT/c7-modulefiles
cat > $ROOT/c7-modulefiles/ufs_gaeac7.oneapi.lua <<'EOF'
-- DRAFT for Gaea C7 with spack-stack 2.2.0, from modulefiles/ufs_gaeac7.oneapi.lua of
-- ufs-community/ufs-weather-model PR 3432 (commit 8eaee8e). Local changes: the caller names the
-- environment (module use <env>/modules/Core); the oneapi swap; cmake and nccmp unpinned;
-- kokkos, kokkos-kernels and arborx loaded if present (try_load). Load after `module reset`.

help([[
  This module loads libraries required for building and running UFS Weather Model
  on the NOAA RDHPC machine Gaea C7 using Intel-2025.3.1.
]])

whatis([===[Loads libraries needed for building the UFS Weather Model on Gaea C7]===])

unload("cray-mpich/9.2.0")

oneapi_ver=os.getenv("oneapi_ver") or "2025.3.1"
unload("oneapi")
load(pathJoin("oneapi", oneapi_ver))

stack_intel_ver=os.getenv("stack_intel_ver") or "2025.3.1"
load(pathJoin("stack-intel-oneapi-compilers", stack_intel_ver))

stack_cray_mpich_ver=os.getenv("stack_cray_mpich_ver") or "9.2.0"
load(pathJoin("stack-cray-mpich", stack_cray_mpich_ver))

cmake_ver=os.getenv("cmake_ver")
if cmake_ver then
  load(pathJoin("cmake", cmake_ver))
else
  load("cmake")
end

load("ufs_common")

nccmp_ver=os.getenv("nccmp_ver")
if nccmp_ver then
  load(pathJoin("nccmp", nccmp_ver))
else
  load("nccmp")
end

setenv("I_MPI_CC", "icx")
setenv("I_MPI_CXX", "icpx")
setenv("I_MPI_FC", "ifx")

setenv("CC","icx")
setenv("CXX","icpx")
setenv("FC","ifx")
setenv("CMAKE_Platform","gaeac7.oneapi")

try_load("kokkos")
try_load("kokkos-kernels")
try_load("arborx")
EOF
```

Load it by hand, the way the harness will:

```bash
module reset
export esmf_ver=9.0.0b17 mapl_ver=2.69.1-esmf-9.0.0b17
module use $HARNESS/modulefiles
module use $ROOT/c7-modulefiles
module use $ENV/modules/Core
module load ufs_gaeac7.oneapi && module list
which icx icpx ifx mpicc cmake ctest
```

Good: no error; `module list` has `oneapi/2025.3.1` (not `2026.0.0`), both `stack-*` modules, `esmf/9.0.0b17`, `mapl/2.69.1-esmf-9.0.0b17`, and about seventeen libraries from `ufs_common`. If it fails, see "If something fails" and send me the output before going on.

## 4. Build on the login node

Start from a clean module environment. The stage scripts load their own modules, but the `uv run` that starts them runs in your shell, and after step 2 that shell has the environment's Python 3.13 packages loaded (`py-numpy`, `py-mpi4py`, …), which must not leak into the harness's own Python:

```bash
module reset; echo "PYTHONPATH=[$PYTHONPATH]"   # empty brackets
cd $HARNESS
C7=(--config-file=$ROOT/gaea-c7-cece.yaml --application cece --root-dir $ROOT)
uv run ufs-chem-assay run "${C7[@]}" --stage source --stage build --stage test --dry-run   # writes the scripts, runs nothing
uv run ufs-chem-assay run "${C7[@]}" --stage source                                        # clones CECE into $ROOT/oneapi/CECE
uv run ufs-chem-assay run "${C7[@]}" --stage build                                         # configure + build, on this node
grep -E "Found MPI|CECE dependency" $ROOT/oneapi/CECE/build/configure.log
```

The build stage loads the modules, runs one `cmake` configure (it fetches Kokkos, GTest and RapidCheck), checks the configure log, and builds with eight jobs. It stops with a message if the log lacks `Found MPI`, `CECE dependency ESMF: system` or `CECE dependency Kokkos: FetchContent`. The script it runs is `$ROOT/scripts/02-build-cece-oneapi.sh`; its log is under `$ROOT/logs/`.

## 5. Run the tests on a compute node

```bash
uv run ufs-chem-assay run "${C7[@]}" --stage test          # submits one job and returns
uv run ufs-chem-assay watch --root-dir $ROOT --only tests  # polls until the job is done, then evaluates it
uv run ufs-chem-assay report --root-dir $ROOT --only tests # the result again, any time later
```

`watch` ends with a line like `tests cece/oneapi: evaluated (exit 0), 577 passed / 0 failed / 0 skipped`. It is safe to stop and start again. The job's files are in `$ROOT/oneapi/tests/cece/`: `tests.yaml` (the record: job id, cluster, verdict), `tests-<job id>.out` (ctest's output), `tests-<job id>.xml` (the junit report).

## If something fails

| What you see | What to do |
|---|---|
| `module load` names an unknown module | Note the name. `module avail <name>` shows whether another version exists; pin it in the config's `module_env` (`<name>_ver: <version>`, dashes as underscores) and `export` the same by hand. Send me the output. |
| The `oneapi` lines of the modulefile fail | Replace the three of them with `swap("oneapi/2026.0.0", "oneapi/2025.3.1")`. |
| `configure did not find MPI`, or a Fortran file cannot find `mpi.mod` / `mpif.h` | Add to the toolchain's `cmake_args`: `-DCMAKE_Fortran_FLAGS=-I/sw/gaea-c7/spack/envs/env_26.06/opt/intel-oneapi-compilers-2025.3.1/cray-mpich-9.2.0-lijx55dkid53jsvrnyfmzcy3i43cbqga/include` (the weather model's own workaround), then run the build stage again. |
| `configure gate failed: CECE dependency Kokkos: FetchContent` | `grep "CECE dependency" $ROOT/oneapi/CECE/build/configure.log` and send it: either the fetch failed, or a Kokkos was found somewhere. |
| The build fails compiling CECE or ESMF-related code | Send the last 50 lines of the newest `$ROOT/logs/02-build-cece-oneapi-*.log`. ESMF 9.0.0b17 is a beta CECE may not have been built against. |
| `watch` says the job finished the moment it was submitted, or `no accounting for job` | `grep cluster $ROOT/oneapi/tests/cece/tests.yaml` should say `c7`. If it says `null`, send me the `sbatch` line and output from `$ROOT/logs/`. |
| The test job dies before ctest (`module: command not found`, a failed `module load`) | Read `tests-<job id>.out`; submit `$ROOT/scripts/04-test-cece-oneapi.sbatch` by hand with `sbatch` to iterate. |
| MPI tests cannot start their ranks | Record `srun --mpi=list`. Set `mpiexec_preflags: --mpi=<one of them>` in the config, run the **build** stage again (the launcher is set at configure time), then the test stage. |
| MPI tests start, then fail with libfabric / CXI errors | Add under `tests_env`: `FI_CXI_RX_MATCH_MODE: hybrid` and `FI_CXI_RDZV_THRESHOLD: 65536` (from the weather model's C7 job), then the test stage again. |
| You want to run a few tests only | Add `--override applications:cece:tests:filter='^<regex>'` to the test-stage command. |
| A test job is still queued and you want to resubmit | `uv run ufs-chem-assay submit-tests --root-dir $ROOT --application cece --resubmit` |
