## Design

### 0. Decisions

1. **Adopt ruff 0.17; do not pin back to 0.12.** Pinning back (`<0.13`) would make the PR green by reverting one of dependabot's thirteen bumps and would leave the project on a linter two major style guides behind, to be paid later with interest. The 35 findings are small, mechanical, and — where they are not improvements — express a convention the project already follows and can state in configuration.
2. **Fix where the rule is right, configure where it misreads a deliberate choice.** Rights: `PLW1510` (an explicit `check=` documents the intent at every call), `RUF043` (a raw string says "this is a regex"), `ISC004` (a parenthesised concatenation cannot be mistaken for a missing comma in a list), `FURB167`, `RUF059`, `EXE001`. Misreads: `BLE001` at the two boundary files and `TRY004` at the usage-error convention — excepted in `ruff.toml` with the reason, by the `T20` pattern.
3. **`BLE001` as per-file exceptions, `TRY004` as a project-wide ignore.** `BLE001` is worth keeping live everywhere except the two files whose job is to swallow failures at a boundary; a per-file entry keeps it on for new code. `TRY004` contradicts a project-wide contract (malformed input is a `ValueError` that the CLI turns into a usage error), so the honest expression is `[lint] ignore`, not a per-file entry that would recur at the next validator.
4. **Pin `ruff>=0.17,<0.18`** — the same "one family" shape the original pin had, with the comment rewritten so it names the right family and the reason (the codebase is formatted with the 2026 style and linted against the 0.16+ default set; a developer's `uv run ruff` resolves from the lock, not from `PATH`).
5. **`[format] exclude = ["design/**"]`.** Records are not maintained code (consistent with `[tool.codespell] skip`, the `yamlfix`/`yamllint` `exclude: ^design/`, and the whitespace hooks). The exclusion is formatter-only: `design/` has no Python files, so lint is unaffected either way, and README/`docs/` keep the formatter (maintained text; both are clean today).
6. **No new tests.** This is a lint-only change: the red is `uv run ruff check .` at 35, the green is `uv run pre-commit run --all-files` clean; the existing tests (audit facts 6–8) guard that behaviour is unchanged, and coverage stays at the 100 % gate because no line is added or removed from the covered paths.
7. **The user commits** (project rule); the changes land uncommitted on the PR's branch for review.

### 2. `ruff.toml` — defaults comment, the two exceptions, the formatter exclusion

```toml

[lint]
# Beyond ruff's default rule set (the expanded set since ruff 0.16 --
# https://docs.astral.sh/ruff/default-rules/ -- which already covers, among

"src/runner.py" = ["T20"]

"src/tests/conftest.py" = ["BLE001"]

[lint.flake8-unused-arguments]
ignore-variadic-names = true

# whitespace hooks skip it for the same reason); README and docs/ keep it.
# The relative glob: a bare "design" matches nothing here (verified, 0.17.0).
exclude = ["design/**"]
```

## Risks and notes

- **Dependabot and the family pin.** With `<0.18` dependabot will propose 0.18 when it ships; the next default-set change lands the same way this one did and is handled the same way (audit, fix or configure, bump the family). That is the intent of the family pin: a ruff major is a code change, reviewed as one.
- **`check=False` is a no-op** by construction (every site reads `returncode`); the risk is nil, and the keyword documents the intent at each call.
- **`chmod +x`** is a tracked mode change; `git diff` shows `old mode 100644 / new mode 100755`. The Docker bind mount in CI sees the checkout's modes, so the hook passes there too.
- **The `[format] exclude`** removes only Markdown under `design/` from formatting today (no `.py` there). If a design artifact ever carries a Python file, it is still linted (lint `exclude` is untouched) but not formatted — acceptable for records.
- **`TRY004` ignore is project-wide**; the one site it covers is the only `isinstance`-and-raise in the tree today. If a genuine type-contract check appears later, `TypeError` is still available — the ignore does not forbid it.
